# ADR-001: Matching Strategy — Levenshtein + Proximity Selection

## Status
Accepted

## Context
User-provided village names are noisy: duplicates, spelling mistakes, and suffix variants are common. The project needs a deterministic, dependency-light matching strategy for Phase 1 that balances recall and precision.

## Decision
Use a two-stage approach:

1. Normalize input and attempt normalized exact matching.
2. If exact matches produce multiple candidate groups across the input list, resolve by selecting candidate combinations that minimize total Euclidean distance between selected coordinates.
3. If no exact matches exist, fall back to Levenshtein edit distance to generate top-3 suggested matches (similarity threshold >= 0.5).

## Consequences
- Pros:
  - Deterministic and reproducible
  - Minimal external dependencies
  - Good recall for realistic typos and variants
  - Proximity provides strong disambiguation signal
- Cons:
  - Euclidean distance approximates geography and must be replaced with haversine for broad-area applications
  - Exhaustive combination search is exponential for many duplicate groups; needs optimization for scale

## Alternatives Considered
- Phonetic matching (Soundex/Metaphone) — insufficient for local variations
- Rapidfuzz/fuzzywuzzy — faster but adds C-extension dependency; planned for Phase 2
- Semantic RAG with vector DB — deferred to Phase 2/3

## Follow-up
- Phase 2: Replace Euclidean with haversine, consider OR-Tools for optimization
- Phase 3: Add FAISS/Pinecone for semantic retrieval and RAG
